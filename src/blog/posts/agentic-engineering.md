# From Vibe Coding to Agentic Engineering

The term has an expiration date. In **April 2026**, at Sequoia Capital's AI Ascent event, Andrej Karpathy — the person who coined *vibe coding* — declared it passé. What comes next, he argued, is **agentic engineering**.

This is not a rebrand. It is a shift in what the human actually does.

## The trajectory

The story has three chapters.

**2023 — "English is the hottest new programming language."** Karpathy's early framing: natural language becomes the interface to computation.

**2025 — Vibe coding.** The practical version: talk to a model, accept the diffs, forget the code exists. Fast, personal, throwaway.

**2026 — Agentic engineering.** The professional version: orchestrate autonomous agents across the full software lifecycle — planning, architecture, generation, testing, security review, deployment, and governance.

By December 2025, Karpathy reported that about **80% of his own code was AI-generated**. The interesting question was no longer whether to generate code, but what humans should do with the time that frees up.

## What changes

Vibe coding centers the *prompt*. Agentic engineering centers the *process*.

| | Vibe coding | Agentic engineering |
| --- | --- | --- |
| Unit of work | A prompt | A goal |
| Human role | React to output | Design, review, govern |
| Scope | One change | Full lifecycle |
| Reliability | Best-effort | Engineered |
| Suitable for | Prototypes | Production systems |

In the agentic model, the human is not accepting diffs — they are setting constraints, defining interfaces, and verifying outcomes that multiple agents produce in parallel.

## What stays the same

The core insight survives: intent can be expressed in natural language, and models can carry much of the mechanical work. The bottleneck moves from *writing code* to *deciding what to build and verifying that it was built correctly*.

IBM frames the same evolution as a shift from **prompt → code** to **intent → AI agent → software**. The emphasis is no longer on generation but on orchestrating every stage of development.

## The skills that matter now

If the future is agentic engineering, the valuable skills change:

- **Specification.** Writing precise goals and acceptance criteria.
- **Context engineering.** Supplying business, architectural, repository, security, and operational context.
- **Verification.** Knowing how to test whether an autonomous system did what you asked.
- **Systems thinking.** Designing the shape of software, not its syntax.
- **Judgment.** Deciding which parts of the lifecycle to delegate and which to keep.

## The honest caveat

Every step of this evolution has been accompanied by the same warnings — and they have not gone away. The *Wall Street Journal*'s "vibe slop" reporting, the rsync controversy, and the open-source erosion paper all point to the same risk: speed without accountability.

Agentic engineering is best understood not as a celebration but as a response. It is what you get when you take the raw capability of vibe coding and wrap it in the engineering discipline that production systems require.

## The bottom line

Vibe coding named a feeling. Agentic engineering may name a practice. The gap between them — between making things fast and making things right — is exactly the work that remains.
